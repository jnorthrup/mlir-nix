Admission and budget explanation:
ScalarJIT.cpp admits LLVM after one successful pure post-oracle observation.
The three native grace checks validate correctness; they do not establish a
high completion rate. A Done resets the native miss streak; retirement requires
64 consecutive Deopts, so mixed low-yield kernels can persist indefinitely.
Each evaluator's tiers share a cap of 16 compilation attempts, including the
pointer engine; retirement frees code but does not refund an attempt. NixOS uses all
16 slots (off: 12). The previously productive `(n: v: v ? value)` at
lib/types.nix:833:32 falls from 2,554 native completions to zero, with its
curried profile stopping at call 1,024. This is consistent with compile-budget
displacement, not proof: refusal reasons / admission ordering are not logged.
Nixpkgs uses 14 slots (off: 9), so its final compile budget is not exhausted.
Curried candidates hit the separate 256-entry cap in every arm. Compile wall
cost increases 41.810000 -> 71.210627 ms and 31.311250 -> 46.324249 ms.

Conservative next work, not a measured performance claim:
1. Keep projections consumed by explicit Boolean logic/predicates, but consider
   excluding bare root Select from the Bool-only tier. A later generic Value-
   return projection recipe could support arbitrary selected results without
   treating non-Bool results as deopts; it must preserve key/base/field demand
   order, original error context, stable-cell lifetime and grace non-forcing.
2. Evaluate a bounded post-oracle admission sample and/or a bounded rolling
   completion/deopt budget. Reuse the one oracle result and pure observer;
   never force extra inputs for profitability. This targets mixed low-yield
   paths that consecutive-miss retirement misses. Preserve activeRuns lifetime
   pins and reentrant compile/retirement checks; add independent counter tests.
3. Callback polymorphism is a lower priority in these profiles: only 134 / 232
   guard misses versus 8,304 / 5,833 additional general deopts. More variants
   would also consume the already-tight compilation budget.
The ordinary Select helper extraction is a separate default-path cost risk;
select-helper-assembly.txt records the local out-of-line call and binary hash.
No causal throughput conclusion follows from these diagnostic profiles.
